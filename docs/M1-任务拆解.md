# M1 开发任务拆解 —— PoC：视频链路 + 键鼠回传

> 项目：rdlink（暂定名）—— Rust 局域网远程桌面
> 阶段目标：跑通最小闭环，**两台真机上 1080p60 看到画面、能操作**
> 预算：约 20~24 小时（按业余时间每天 1~2 小时，两周）
> 主控端：RTX 4060 laptop（多屏）｜被控端：MX250（Pascal NVENC）

---

## 0. M1 范围守卫（明确不做的事）

| 不做 | 原因 / 归属 |
|------|------------|
| UI 界面（egui 面板、托盘） | M1 用 CLI + toml 配置，M3 再做 |
| 密码认证 | M3；但传输层自带 rustls 加密 + 证书指纹 pin |
| 剪贴板 / 文件传输 / 电源 / 进程管理 | M3 |
| Windows 服务常驻、开机自启 | M3；M1 手动启动 `host.exe` |
| 多屏选择、DPI 映射 | M4；M1 固定被控端主屏、坐标线性缩放 |
| 断线重连 | M1 断了就重启进程 |
| 双模式（办公/游戏参数档） | M2；M1 固定一套低延迟参数 |
| 音频 | 永久砍掉（需求确认不需要） |

## 1. M1 锁定的技术选型

| 层 | 选型 | 说明 |
|----|------|------|
| 屏幕捕获 | `windows-capture` crate（Windows.Graphics.Capture） | 活跃维护的 WGC 绑定，输出 D3D11 纹理 |
| 视频编码 | `ffmpeg-the-third` + 系统 FFmpeg DLL，`h264_nvenc` | NVENC 原生支持 bgr0/bgra 输入，省一次 swscale |
| 编码兜底 | 同接口封装 `libx264 ultrafast zerolatency` | NVENC 不可用时自动切换 |
| 传输 | `quinn`（QUIC）+ `rustls` 自签证书 | M1 视频走可靠 stream（见决策 D1） |
| 解码 | `avcodec` + `d3d11va` 硬解（NVDEC） | 4060 解码无压力；软解做兜底 |
| 渲染 | `winit` 全屏 borderless + `wgpu` | M1 CPU 端 NV12→BGRA 后上传单纹理（见决策 D2） |
| 输入捕获 | winit 窗口事件（键盘 + 鼠标） | M2 升级 Raw Input（相对鼠标模式） |
| 输入注入 | `windows` crate `SendInput` | 绝对坐标 + 虚拟键码 |
| 序列化 | `serde` + `bincode`，length-prefix 帧 | 简单高效 |
| 配置 | `toml` 文件 | 端口 / 码率 / preset / 分辨率上限 |

### 设计决策记录（为什么这么做）

- **D1 视频走 QUIC stream（可靠）而非 datagram**：局域网丢包率≈0，可靠流的队头阻塞实际不触发；实现省一天。M2 迁移到 datagram + 分片重组 + 丢旧帧时，transport 层留 trait 抽象双实现。
- **D2 M1 允许两次显存拷贝**（捕获 GPU→CPU map，渲染 CPU→GPU 上传）：预算 +4~6ms，换实现速度。M2 做 D3D11 零拷贝直通。
- **D3 渲染 vsync 默认关**（present mode Immediate/Mailbox）：延迟优先，M1 提供配置开关用于对比测量。
- **D4 起播等待 IDR**：client 在收到第一个 IDR 帧前丢弃数据，避免头几帧花屏。

## 2. 协议与数据结构（T1 产出物预览）

```rust
// crates/proto/src/lib.rs（示意）
#[derive(Serialize, Deserialize)]
enum Message {
    // Control stream（双向，可靠）
    Control(ControlMsg),      // Hello / VideoInfo{width,height,extradata} / Stats / Bye

    // Video stream（host→client，M1 可靠流）
    VideoFrame { pts_us: i64, key: bool, data: Vec<u8> },  // data = 完整一帧 H.264

    // Input stream（client→host，可靠有序）
    Input(InputEvent),
}

#[derive(Serialize, Deserialize)]
enum InputEvent {
    MouseMove { x: u32, y: u32 },            // 被控端屏幕像素坐标（client 已换算）
    MouseButton { button: u8, down: bool },
    MouseWheel { dx: i32, dy: i32 },
    Key { vk: u16, down: bool },             // Windows 虚拟键码
    UnicodeChar { ch: u32 },                 // 文字输入兜底（KEYEVENTF_UNICODE）
}
```

帧封装：`[u32 length][bincode Message]`，TCP 式 length-prefix，QUIC stream 天然保序。

坐标映射（client 侧完成）：
```
窗口客户区 (px, py) → 归一化 (px/w, py/h) → 被控端像素 (nx * host_w, ny * host_h)
```
被控端分辨率通过 Control::VideoInfo 在建流时下发，client 缓存。

### T2 transport：QUIC 连接与通道（1.5h）

- [ ] `scripts/gen-cert.ps1`：生成自签证书，指纹写进两边 config（M1 的"防误连"即证书 pin）

- [ ] 验收：两台真机跑 echo/吞吐 benchmark，吞吐 >200Mbps、RTT <2ms

### T3 host 捕获：WGC 抓帧（2~3h）

- [ ] `windows-capture` 捕获主显示器，拿到 D3D11 纹理
- [ ] M1 管线：D3D11 texture → CopyResource 到 staging texture → Map → 系统内存 BGRA buffer
- [ ] 分辨率策略：原生分辨率直出；若被控屏 >1080p 且 T4 编码吃力，加 D3D11 blit 降到 1080p（配置项 `max_height`）
- [ ] 帧率特性确认：WGC 按脏区驱动，静止桌面不产帧——M1 接受（client 保持最后一帧），测试时动鼠标即出帧
- [ ] 验收：独立小 demo（`host --capture-demo`）连续抓帧 30 秒，打印实际 fps 和每帧 BGRA 尺寸，另存 5 张 PNG 肉眼检查

---

### T4 host 编码：NVENC H.264（3~4h）⚠️ 关键路径 + 最大风险

- [ ] ffmpeg-the-third 打开 `h264_nvenc` 编码器，M1 固定参数档：

| 参数 | 值 | 理由 |
|------|-----|------|
| preset | `p1`（速度最快档） | MX250 性能优先，画质靠码率补 |
| tune | `ull`（ultra low latency） | 禁用前视/B帧缓冲 |
| bf | 0 | 无 B 帧，最低延迟 |
| delay / async depth | 0 / 1 | 输入一帧立即出一帧 |
| rc + bitrate | CBR 50Mbps | 局域网带宽无压力，画质换余量 |
| gop | 250，IDR 起播 | M1 可靠流不需要 intra-refresh |

- [ ] 输入直接喂 **BGRA**（NVENC 原生支持 bgr0 输入，内部转 NV12，省掉 swscale）
- [ ] 捕获帧 → `av_frame` 包装（wrap 系统内存 buffer，避免拷贝）→ `send_frame` / `receive_packet`
- [ ] 启动时提取 `extradata`（SPS/PPS）通过 Control::VideoInfo 下发
- [ ] **兜底分支**：NVENC 打开失败自动 fallback `libx264 ultrafast + zerolatency + tune zerolatency`（同一 trait 封装），日志高亮警告
- [ ] 编码延迟打点：`receive_packet` 时刻 − 对应帧 `capture` 时刻
- [ ] 验收：`host --encode-demo`：T3 抓帧 → 编码 → 落盘 `out.h264` → ffplay/PotPlayer 播放正常；单帧编码耗时日志 p95 < 10ms
- [ ] 坑位预案：
  - avcodec 找不到 DLL / 版本不匹配 → 回 T0 锁版本
  - MX250 上 nvenc 会话数限制（消费卡驱动历史限制 3 路并发，单路无碍）
  - ffmpeg-the-third API 与 ffmpeg 7.x 字段对应，编译报错查该 crate 的示例

---

### T5 client 解码（2h）

- [ ] avcodec `h264` 解码器 + `d3d11va` hwaccel（4060 NVDEC）
- [ ] M1 路径：NV12 硬解输出 → 下载系统内存 → **CPU 端 swscale NV12→BGRA**（4060 机器 CPU 强，够用；M2 改 shader 直转）
- [ ] 起播逻辑（决策 D4）：缓冲区尚未收到 `key=true` 的 IDR 帧前，丢弃所有 packet；首 IDR + extradata 到位后开始 decode
- [ ] 解码延迟打点：`receive_frame` 时刻 − packet 发送时刻（用 Control 通道对时或直接用 pts 差近似）
- [ ] 软解兜底：hwaccel 初始化失败自动退 sw 解码，日志提示
- [ ] 验收：`client --decode-demo` 收流落盘 .h264 回放正常；解码耗时 p95 < 5ms

---

### T6 client 渲染（3h）

- [ ] winit 无边框全屏窗口（`Fullscreen::Borderless` 指定主显示器；配置项 `monitor_index` 为 M4 多屏预留）
- [ ] wgpu：BGRA 纹理上传 + 直通 shader + swapchain present
- [ ] present mode 配置化：`Immediate`（默认，低延迟）/ `Fifo`（vsync 对照测量用）
- [ ] 实际呈现帧率统计（present 计数 / 秒，写窗口标题栏：`rdlink 58.9fps | 22ms` 格式，M1 的"HUD"就是标题栏，零成本）
- [ ] 本地测试模式：`client --render-demo` 不走网络，直接渲一张动态测试图（彩条 + 移动时钟），验证渲染管线独立于网络
- [ ] 验收：render-demo 稳定 60fps（vsync off 时应能 >60）；全屏/窗口切换（F11）不崩溃

### T7 视频链路集成（1~2h）🎉 第一个端到端里程碑

- [ ] host：T3 捕获线程 → T4 编码 → T2 Video stream 发送（捕获与编码可同线程流水，M1 不做线程池）
- [ ] client：Video stream 接收 → T5 解码 → T6 渲染，异步任务三段流水
- [ ] 建连时序：QUIC 连接 → Control 通道交换 Hello + VideoInfo（分辨率、extradata）→ 开 Video stream → IDR 起播
- [ ] 验收（真机）：`host.exe` 起来后，`client.exe --host 192.168.x.x` 1 秒内出画面，拖动被控端窗口画面跟手，60fps（标题栏确认）

### T8 键鼠正向链路（2~3h，可与 T3~T6 并行）

**client 侧：**
- [ ] winit 事件（KeyboardInput / CursorMoved / MouseInput / MouseWheel）→ `InputEvent` → Input stream
- [ ] 坐标映射：客户区坐标 → 归一化 → 被控端像素（用 VideoInfo 的分辨率）
- [ ] **本地热键不注入**：`Ctrl+Alt+Q` 退出、`F11` 全屏切换、`Ctrl+Alt+T` 释放鼠标（M1 固定窗口模式不需要，预留）
- [ ] 虚拟键码转换：winit 的 `KeyCode` → Windows VK（建映射表，覆盖字母/数字/F 键/方向键/修饰键）

**host 侧：**
- [ ] `SendInput` 注入：
  - 鼠标：`MOUSEEVENTF_ABSOLUTE | MOVE`，坐标再归一化到 0~65535
  - 键盘：VK 扫描码注入；**方向键/Insert 等扩展键必须带 `KEYEVENTF_EXTENDEDKEY`**（经典坑）
  - 文字兜底：收 `UnicodeChar` 时走 `KEYEVENTF_UNICODE`
- [ ] 事件合并：MouseMove 事件合并最新（同 tick 只发最后一次位置），减少流量
- [ ] 验收（真机）：被控端开记事本——鼠标移动/点击/拖拽正常，键盘打字正常，Win 键、方向键正常；**被控端输入法切英文测试**（IME 注入是 M4 议题，M1 记录已知限制）

## 5. 风险登记

| 风险 | 概率 | 影响 | 预案 |
|------|------|------|------|
| MX250 驱动掐 NVENC / 会话限制 | 低 | 高 | T0 命令行先行验证；x264 兜底分支 |
| ffmpeg DLL 版本地狱 | 中 | 中 | 锁版本 + DLL 随程序目录分发 |
| windows-capture API 与文档不符 | 中 | 低 | 锁 crate 版本，看官方示例改 |
| wgpu 全屏在多屏主控端选错屏 | 中 | 低 | monitor_index 配置；render-demo 先验证 |
| Alt+Tab 等系统组合键被主控端系统吃掉 | 高（已知） | 低 | M1 记录为已知限制，M4 用键盘钩子/捕获模式解决 |
| 被控端 IME 中文输入 | 高（已知） | 低 | M1 英文输入法测试；UnicodeChar 兜底；M4 专项 |
| 静止桌面 WGC 不出帧导致"卡死"错觉 | 中 | 低 | README 说明；后续加保底心跳帧 |
