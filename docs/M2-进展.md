# M2 进展（延迟优化）

日期：2026-09-29（主控端会话）

## 今日结论

### 插桩发现的真实瓶颈（修正了两个误判）

1. ~~"enc 13ms 是 x264 软编"~~ → 实际 **h264_qsv 核显硬编**（NVENC 被 R580 掐死后 QSV 一直成功兜底）。
2. QSV 分段计时（150 帧 p50）：

   | 分段 | 耗时 | 说明 |
   |---|---|---|
   | BGRA 拷贝 | 1.9ms | 全帧 memcpy（可省） |
   | **swscale BGRA→NV12** | **9.3-10.6ms** | **真瓶颈：CPU 软件转换** |
   | QSV 提交+取包 | 5.0ms | 硬编本体，已接近下限 |

   → 编码总 p50 ~17ms 里 **12ms 是 CPU 侧准备**；M2-3 零拷贝（D3D11 纹理直喂 QSV/VPP GPU 转换）可全歼这 12ms，enc 有望 ~5ms，60fps 解锁。

### 首帧优化成果（提交 4163d7a + 125b2a3）

| 场景 | 优化前 | 优化后 |
|---|---|---|
| 被控端热会话首帧 | 467-907ms | **~380ms** |
| 强杀重连首帧 | 900-1470ms | **~380ms**（M1 时曾 8.8s） |
| 本机 NVENC 冷启动 | 840ms | **~360-500ms** |

手段（按贡献排序）：
1. video/input 任务先于首帧 nudge 启动（首帧不再在 channel 里等 300ms 兜底，插桩抓出的纯 bug）
2. 编码器跨会话复用（QSV 打开 201-763ms → 0ms；复用首帧 force_key 强制 IDR + forced_idr 选项，实测 SPS/PPS 跟随 IDR 正常下发、客户端即时起播）
3. 会话回收三步并行（stop/video/input 串行最坏 900ms → 封顶 300ms）
4. 3s 无 Ping 失联看门狗（强杀的 client 僵尸会话不再等 QUIC idle 10s）
5. NVENC 探测结论进程级缓存（失败一次不再每会话重试）
6. WGC 保活**不做**：热激活实测仅 14-46ms，不值得架构复杂度
