# M3 任务拆解：实用功能

目标：把 rdlink 从"能看能控"升级为"日常主力"——剪贴板互通、文件互传、远程电源/
进程管理、密码认证。沿用协议 v2 的 QUIC 三流架构，**协议升 v3**（ControlMsg 新增
变体破坏线格式，两端同仓库同步升级，部署链路已具备）。

> 前置状态：M2.5 已交付守护循环/自动重连/计划任务硬化，"常驻服务化"从 M3 划掉
> （bat 守护 + 登录自启 + 崩溃自愈已覆盖需求，Windows Service 反而会进 Session 0
> 破坏 WGC 采集）。

## 任务总览（按用户价值排序）

|---|---|---|---|---|
| M3-1 | 剪贴板同步 | 日常最高频（两边复制粘贴） | 1d | 无（纯后台，零 UI） |

## M3-1 剪贴板同步（文本，双向，纯后台）

思路：两端各自监听本机剪贴板变化 → 变了就发 `ControlMsg::ClipboardSync` → 对端写
入本机剪贴板。用内容指纹抑制回环（A 写→同步到 B→B 检测变化又同步回 A 的死循环）。

- **T1.1 协议**：`ClipboardSync { hash: u64, text: String }`（hash = 内容 FNV-64，
  接收端发现 hash == 本端 last_written_hash 则静默忽略）。
- **T1.2 host 侧剪贴板线程**：host 是控制台程序无窗口——起专用线程建 message-only
  窗口（HWND_MESSAGE）+ `AddClipboardFormatListener`，收 `WM_CLIPBOARDUPDATE` →
  `OpenClipboard/GetClipboardData(CF_UNICODETEXT)` → 发协议消息。写入方向：收到同步
  → 同线程 SetClipboardData，并记录 last_written_hash。
- **T1.3 client 侧**：`arboard` crate；Windows 下无监听事件，500ms 轮询比对上次
  hash（桌面场景足够，实现最简）。读写同一把锁。
- **T1.4 防御细节**：>1MB 文本丢弃+日志（防链路冲击，分片 M4）；剪贴板被占用
  （OpenClipboard 失败）重试 3 次弃；UIPI：从提权窗口复制的内容本端写入失败要静默
  计数，不能崩。
- **验收**：两端互拷中英文 <1s 出现；1MB 文本同步且链路无卡顿；连续快速拷贝 10 次
  无回环风暴；录屏确认不影响 fps。

## M3-0 client egui 覆盖层（UI 地基）

现状 client 是手写 wgpu 直绘远端画面，没有任何 UI 元素。M3 需要：传输进度、远端
文件列表、进程表格、电源菜单（防误触确认）、密码输入框——全部塞系统对话框体验崩坏。

- **T0.1**：集成 `egui_winit + egui_wgpu`，渲染顺序：远端画面 → egui 层。
- **T0.2 交互开关**：`Ctrl+Alt+U` 呼出/收起"控制面板"；**面板打开时鼠标键盘事件
  全部喂 egui、不转发 host**（否则点面板按钮会点到远端）；收起后恢复转发。Esc 仍是
  本地退出、F11 全屏，语义不变。
- **T0.3 面板骨架**：标签页：传输 / 进程 / 电源 / 设置（M3-5 密码住这里）。
- **T0.4**：标题栏逻辑保留（fps/e2e/重连状态），与面板共存。
- **验收**：面板开关时输入路由正确（面板开着打字不进远端）；帧率损耗 <2fps；
  全屏下面板正常显示。

## M3-2 文件传输

协议：握手后按需开**第 4 条 bi stream**（文件流，复用现有 length-prefix codec），
消息：

```text
FileListReq{path} → FileListReply{entries:[{name,size,is_dir,mtime}]}
FileRequest{id, dir:Up|Down, name, size} → FileAccept{id} | FileReject{reason}
FileChunk{id, offset, data ≤256KiB}  ←流式，接收方每 4MiB 回 FileAck{id, offset}
FileDone{id, sha256} → FileOk{id} | FileFail{id, reason}
```

- **T2.1 host 收发**：上传落 `%USERPROFILE%\Downloads`（rdlink.toml [host]
  download_dir 可改），重名追加 (1)；下载按请求路径读取；SHA-256 尾校验。
- **T2.2 client 上传**：**拖文件到窗口即传**（winit `DroppedFile` 事件 → Downloads），
  面板显示进度条。零对话框，摩擦最低。
- **T2.3 client 下载**：面板"传输"页列出 host Downloads（FileListReq，M3 只浏览
  这一个目录，全盘浏览器 M4）→ 勾选 → rfd 选本机保存位置 → 传输 + 进度。
- **T2.4 风险控制**：文件流与视频流共享 QUIC 连接，大文件传输会挤占视频（QUIC 流间
  公平调度）。M3 接受"传输期间 fps 下降"并记录实际程度；若不可接受，M4 做视频
  码率运行时降档。
- **验收**：100MB 文件双向 ≤10s（局域网千兆应远快于此）；传输中视频降帧不崩溃、
  传输完自动恢复；传 1KB 小文件不粘包；错误路径（只读目录/不存在）给 Reject 而非断流。

## M3-3 电源控制

- **T3.1 协议+执行**：`PowerAction{Lock|Sleep|Shutdown|Restart}`。host 执行：
  Lock=`LockWorkStation`；Sleep=`SetSuspendState`；Shutdown/Restart=
  `InitiateSystemShutdownExW`（host 交互用户权限足够）。
- **T3.2 client**：面板电源区四按钮，Shutdown/Restart 必须 egui 二次确认；
  Lock/Sleep 直接执行。
- **T3.3 自愈红利验证**：Restart 后被控端登录自动上线（M2.5 AtLogOn 触发），
  client 自动重连接上——这链路要端到端实测一次，是"挂机党"核心场景。
- **验收**：四动作实测；重启→登录→client 自动恢复画面全程无人工。

## M3-4 进程管理

- **T4.1 协议**：`ProcListReq` → `ProcListReply{entries:[{pid,name,cpu,mem_mb}]}`；
  `ProcKill{pid}` → `ProcKillResult{ok, reason}`。host 用 `sysinfo` crate（自带
  CPU 两次采样，省手写 Toolhelp+性能计数）。
- **T4.2 client**：面板"进程"页：名称搜索 + 表格（PID/名称/CPU/内存，按 CPU 排序）
  + 刷新按钮（手动刷新，不做自动轮询防链路占用）+ 结束任务（确认框）。杀系统进程
  被拒时显示 reason。
- **验收**：列表与任务管理器数量级一致；杀一个自己起的测试进程成功；杀 lsass 被拒
  且连接不受影响。

## M3-5 密码认证

需求回口："固定密码"。现有证书指纹 pinning 防中间人/假冒 host；密码防"知道 IP 的
局域网第三方"。双因素收口。

- **T5.1 凭据**：`host --set-password` 交互式设置 → argon2id 派生 32B 密钥 K 存
  rdlink.toml（[host] auth_key）。**安全边界明示**：K 等效密码，配置文件泄露=密码
  泄露（本机单用户场景可接受，M4 可改 verifier 方案）。
- **T5.2 握手扩展（防重放）**：Hello{capable} → HelloAck{nonce(32B)} → 
  `AuthProof{proof = SHA256(K ‖ nonce)}` → host 比对。失败 3 次 = 断连 + 60s 拒绝
  （防爆破）。无 auth_key 配置 → 跳过认证（向后兼容现状）。
- **T5.3 client**：设置页输入密码 + "记住"（存 rdlink.local.toml，明文，标注风险）。
- **验收**：错密码 3 次内拒连+延迟生效；对密码一次通过且握手增加 <50ms；不设密码
  时行为与现在完全一致。

## 风险表

| 风险 | 应对 |
|---|---|
| egui 与输入转发互相打架 | T0.2 的路由开关单独验证；面板态不转发是硬规则 |
| 文件传输挤占视频 | M3 接受+实测记录；不可接受则 M4 视频码率运行时降档 |
| 剪贴板回环风暴 | 内容指纹抑制 + 1MB 上限；压测 10 连拷 |
| 关机把 bat/任务弄僵 | Restart 自愈链路端到端实测（T3.3），Shutdown 前先 Lock 验证 |
| 协议 v3 升级期间两端版本错位 | 两端同仓库同步部署（既有流程）；握手版本不一致直接拒绝并打印明确错误 |
