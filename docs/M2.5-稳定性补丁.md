日期：2026-09-30 深夜（提交 aa6f1be）。背景：用户需要长时间挂着控制，审计发现四处
卡死/停服缺口（见 M2-基线数据.md 测量纪律一节）。全部完成并双端部署验证。

## 四项补丁

| # | 补丁 | 防的是什么 | 实现 |
|---|---|---|---|
| 1 | host 视频活性看门狗 | 捕获线程/GPU 死亡（TDR、驱动重置）时 control 心跳照常、画面冻结——原看门狗只看 Ping 看不到 | video 任务 4s 无帧→nudge 探活（静止桌面正常，nudge 必出帧）；连续 3 次（~12s）探不出→判死→watch 通道通知 control 循环回收会话 |
| 2 | client 自动重连 | Wi-Fi 抖动/host 重启即断线退出，需手动重开窗口 | stream_loop 改监督循环：断线后指数退避 1s→2s→4s→8s→10s 封顶；窗口/渲染复用（保留最后帧），标题栏显示"重连中（第 N 次）"；输入通道按会话重建（断线期事件作废不重放）；解码器每会话新建（分辨率变化安全） |
| 3 | bat 守护循环 + 隐藏窗口 | host.exe 崩溃无人拉起；黑窗口被 Ctrl+C（已发生 3 次） | start-host.bat 改无限循环：host.exe 退出 2s 后自动拉起；start-host-hidden.vbs 以无窗口方式启动 bat（wscript，误 Ctrl+C 物理不可能） |
| 4 | 日志轮转 | host-run.log 无限增长 | 每次循环启动 host 前检查 >16MB 归档为 host-run.old.log（保留一代） |

## 计划任务硬化（rdlink-host 重建）

| 项 | 旧 | 新 |
|---|---|---|
| 触发 | 无（手动 /Run） | **用户登录时自动启动** |
| 电源 | 切电池即停 | 电池上允许运行、不因切电池停止 |
| 执行时限 | 默认 72h | 无限制 |
| 启动方式 | 直接跑 bat（黑窗口） | wscript 隐藏启动 |
| 崩溃自愈 | 无 | bat 循环 2s 拉起 |

## 验证记录

- 看门狗零误报：25s 静止挂机会话正常（nudge 探活 15 关键帧 = gop 理论值），无失活回收
- 本地强杀 host → client 日志时间线：`video 流错误 → 会话结束（连接丢失）→ 第 1 次重连（1s 后重试）→ 已连接（握手 2.2ms）`，自动恢复 60fps
- 被控端端到端：host 崩溃（taskkill）→ bat 2s 拉起新实例 → client 1s 退避自动重连（握手 9.7ms）→ 恢复 50-55fps，**总中断 ~3-4s，全程无人干预**

## 运维约定变更（重要）

- **故意停服**必须 `schtasks /End /TN rdlink-host`（终止任务树含 bat 循环）；
  只 `taskkill host.exe` 会被 bat 2 秒后拉起（这是特性不是 bug）。
- 部署流程相应改为：`schtasks /End` → `taskkill /F /IM host.exe` → git pull → 构建 → `schtasks /Run`。
- 黑窗口不复存在；要看日志看 host-run.log。
